Independent Cube 3D workflow study

Making Cube 3D usable on a 6GB laptop GPU.

CubeLite Studio is a local test harness for Roblox's open-source Cube 3D model. The project focuses on low-VRAM inference, repeatable benchmarks, mesh inspection, and Roblox-oriented export folders.

Current status

The low-VRAM path works. The asset quality still needs curation.

The original high-memory path hit CUDA out-of-memory on this machine at roughly 5.98GB peak VRAM. CubeLite's staged runner completed real Cube 3D v0.5 generations by loading CLIP, GPT, and shape decoding as separate stages.

That is the useful engineering result so far. The generated meshes are not all good. Some are readable Roblox-style props, some are mixed, and some are failures. The next step is stricter candidate search and better cleanup before this should be sent outside.

What CubeLite adds

A measured local workflow around the model

Staged inference

CLIP runs on CPU, GPT runs on GPU for token generation, then the shape decoder loads after GPT is unloaded.

Candidate search

Run seeded variations and record which prompt, seed, sampling setting, and profile produced each mesh.

Mesh inspection

Generate single previews and multi-angle plates, then score mesh size, triangle count, and import risk.

Export package

Bundle OBJ files, metadata, benchmark summary, render plate, and Roblox import notes in one folder.

Before sharing externally

What still has to improve

  • Run a larger seeded candidate search for a small set of Roblox props instead of showing first-pass generations.
  • Replace weak examples with only the best meshes, plus one honest failure section in the technical report.
  • Import the best candidates into Roblox Studio and document scale, collision, normals, and cleanup needs.
  • Add a stricter visual review field so a 100/100 readiness score does not imply the model looks good.
  • Keep the texture story honest: Cube 3D is geometry-first today; texture generation should not be implied.
